# Logging

This guide describes logging and mapped diagnostic context (MDC) support in Helidon SE.

## Helidon Logging

Helidon modules use the Java Platform Logging API (`System.Logger`). Helidon SE
projects generated by the archetypes include `helidon-logging-jul` and use Java
Util Logging (JUL) by default. You can also use Log4j or SLF4J, as described in
[Using Log4j or SLF4J](#using-log4j-or-slf4j).

## Initialization

Call `LogConfig.configureRuntime()` early in an SE application's `main` method,
before other Helidon code logs messages. Logging configuration runs once during
class initialization; later calls do not reload it. 

## Customizing Java Util Logging

Most Helidon examples include a `logging.properties` file on the classpath.
For example:

```properties [logging.properties]
handlers=io.helidon.logging.jul.HelidonConsoleHandler

java.util.logging.SimpleFormatter.format=%1$tY.%1$tm.%1$td %1$tH:%1$tM:%1$tS.%1$tL %4$s %3$s !thread!: %5$s%6$s%n

# Global logging level; individual loggers can override it.
.level=FINE
```

`HelidonConsoleHandler` writes to standard output. It defaults its handler level
to `ALL`, leaving level filtering to loggers, and uses `HelidonFormatter` by
default. `HelidonFormatter` supports JUL `SimpleFormatter` formats, MDC tokens
such as `%X{name}`, and `!thread!` for the current thread.

To set a different level for one package, add an entry such as:

```properties [logging.properties]
io.helidon.webserver.level=INFO
```

### JSON Log Output

To output one JSON object per log record, configure the console handler to use
`HelidonJsonFormatter`:

```properties [logging.properties]
handlers=io.helidon.logging.jul.HelidonConsoleHandler
io.helidon.logging.jul.HelidonConsoleHandler.formatter=io.helidon.logging.jul.HelidonJsonFormatter
io.helidon.logging.jul.HelidonJsonFormatter.fields=ts:%1$tQ,level:%4$s,logger:%3$s,message:%5$s,trace_id:%X{trace_id}
.level=INFO
```

The `fields` property is a comma-separated list of `name:value-format` pairs.
The `value-format` can use JUL `SimpleFormatter` arguments, MDC tokens such as
`%X{trace_id}`, and Helidon’s `!thread!` token. If `fields` is absent, it is derived
from the value of `java.util.logging.SimpleFormatter.format` if that property is set;
otherwise it uses a built-in JSON format.

## Using Log4j or SLF4J

Helidon's `System.Logger` calls can be routed to another framework through its
Java Platform Logging provider. The Helidon Log4j and SLF4J integration modules
include the corresponding provider and add MDC propagation support. If your
application also uses JUL directly, add a JUL bridge to route those messages to
the same framework. In a generated SE project, replace the
`helidon-logging-jul` dependency with the integration module for the framework
you choose so that only one Helidon logging provider is present.

### Log4j

Add these dependencies to a project that uses Helidon's dependency management:

```xml [pom.xml]
<dependency>
    <groupId>io.helidon.logging</groupId>
    <artifactId>helidon-logging-log4j</artifactId>
</dependency>
<dependency>
    <groupId>org.apache.logging.log4j</groupId>
    <artifactId>log4j-api</artifactId>
</dependency>
<dependency>
    <groupId>org.apache.logging.log4j</groupId>
    <artifactId>log4j-core</artifactId>
</dependency>
<dependency>
    <groupId>org.apache.logging.log4j</groupId>
    <artifactId>log4j-jul</artifactId>
</dependency>
```

`helidon-logging-log4j` supplies the Log4j Java Platform Logging provider and
Helidon MDC integration. `log4j-jul` can bridge JUL calls when configured for
that purpose. See the [Helidon Log4j example][log4j-example].

### SLF4J and Logback

The following example uses Logback as the SLF4J provider. Set
`version.lib.logback` to the Logback version used by your project.

```xml [pom.xml]
<dependency>
    <groupId>io.helidon.logging</groupId>
    <artifactId>helidon-logging-slf4j</artifactId>
</dependency>
<dependency>
    <groupId>org.slf4j</groupId>
    <artifactId>slf4j-api</artifactId>
</dependency>
<dependency>
    <groupId>org.slf4j</groupId>
    <artifactId>jul-to-slf4j</artifactId>
</dependency>
<dependency>
    <groupId>ch.qos.logback</groupId>
    <artifactId>logback-classic</artifactId>
    <version>${version.lib.logback}</version>
</dependency>
```

`helidon-logging-slf4j` supplies the SLF4J Java Platform Logging provider and
Helidon MDC integration. To route JUL calls as well, install the JUL bridge
before those calls occur:

```java
org.slf4j.bridge.SLF4JBridgeHandler.removeHandlersForRootLogger();
org.slf4j.bridge.SLF4JBridgeHandler.install();
```

See the [Helidon SLF4J example][slf4j-example].

## Mapped Diagnostic Context (MDC)

MDC associates values such as a request ID or current user with log messages.
Helidon's `HelidonMdc` API works with JUL, Log4j, and SLF4J. Helidon propagates
MDC values across threads when using its context-aware executors.

To use MDC, include a supported logging module, set values in your code, and
configure the logger's output format to display them.

### Values Provided by Helidon

When Helidon tracing is present, the `trace_id` MDC key supplies the current
span's trace ID, or `none` when no span is active. OpenTelemetry integration
also supplies `span_id` and `baggage` when its global configuration is enabled.

### Setting Values

Use `io.helidon.logging.common.HelidonMdc` to set fixed or computed values:

```java
HelidonMdc.set("name", "Joe");
HelidonMdc.set("otherName", () -> retrieveStringValue());
```

The supplier form lets `HelidonMdc` compute the current value when it reads the
MDC entry.
Call `HelidonMdc.remove(key)` or `HelidonMdc.clear()` when the values should no
longer apply. You can also use a framework-specific API, such as `org.slf4j.MDC`
or `org.apache.logging.log4j.ThreadContext`.

### JUL Output

Use `HelidonConsoleHandler` or `HelidonFormatter` to render MDC tokens in JUL
output. The token `%X{name}` reads the MDC entry named `name`:

```properties [logging.properties]
handlers=io.helidon.logging.jul.HelidonConsoleHandler
java.util.logging.SimpleFormatter.format=%1$tY.%1$tm.%1$td %1$tH:%1$tM:%1$tS %4$s %3$s !thread!: %5$s%6$s "%X{name}"%n
.level=INFO
```

### SLF4J and Logback Output

Configure Logback using `logback.xml` on the classpath. `%X{name}` inserts the
MDC entry named `name`:

```xml [logback.xml]
<configuration>
    <appender name="STDOUT" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{HH:mm:ss.SSS} %-5level [%thread] %logger{36} - %msg %X{name}%n</pattern>
        </encoder>
    </appender>
    <root level="INFO">
        <appender-ref ref="STDOUT" />
    </root>
</configuration>
```

### Log4j Output

In a Log4j `PatternLayout`, use `%X{name}` to include an MDC value:

```xml
<PatternLayout pattern="%-5p [%t]: %X{name} %m%n"/>
```
