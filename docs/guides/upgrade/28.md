# 28 Upgrade

## Feature Metadata

Helidon 28 removes support for `META-INF/helidon/feature-metadata.properties`.
Modules that provide only this legacy file no longer appear in the feature list
or receive feature status diagnostics.

Use the `io.helidon.common.features.api.Features` annotations on `module-info.java`
with the `helidon-common-features-codegen` annotation processor to generate the
JSON feature registry. The version 2 `feature-registry.json` format continues to
be supported, including registries discovered through the Helidon metadata manifest.

## GraalVM Native Image

Helidon 28 removes the remaining GraalVM Native Image integration, including
reflection and resource configuration, module compatibility annotation processing, and
Native Image packaging tests. GraalVM Native Image is not supported.

The following Native Image APIs remain available for compatibility and are
deprecated since 28.0.0 with `forRemoval = true`:

- `io.helidon.common.NativeImageHelper` and `io.helidon.common.Reflected`
- `io.helidon.common.features.api.Features.Aot`
- `io.helidon.common.features.metadata.Aot`, `FeatureMetadata.aot()`, and the
  corresponding builder methods
- `io.helidon.common.features.HelidonFeatures.nativeBuildTime(ClassLoader)`
- `ProcessRunner.ExecMode.NATIVE` in the integration-test harness

Remove uses of these APIs when upgrading; they are planned for removal in a future
release.

The feature annotation processor no longer handles `Features.Aot`, so module
annotations no longer add an `aot` property to generated feature registries.
Existing version 2 JSON registries retain that property through the deprecated
metadata APIs and serialization. Normal feature discovery and logging no longer
emit Native Image compatibility diagnostics. The deprecated `nativeBuildTime`
method retains its legacy diagnostics when called explicitly.

Project Leyden and the JDK AOT cache used by [jlink packaging](../jlink.md) are
unaffected. General feature metadata, service discovery, JVM packaging, and
logging initialization remain supported.

## Config Polling and Watcher Executors

The `executor(ScheduledExecutorService)` methods on
`ScheduledPollingStrategy.Builder`, `PollingStrategies.ScheduledBuilder`, and
`FileSystemWatcher.Builder` now reject `null` with `NullPointerException`.
`ScheduledPollingStrategy.create(RecurringPolicy, ScheduledExecutorService)`
also requires a non-null executor.

Replace `builder.executor(null)` with `builder.clearExecutor()` to restore the
default selection, or omit the executor setting on a new builder. Replace
`ScheduledPollingStrategy.create(policy, null)` with
`ScheduledPollingStrategy.create(policy)`.

Executor ownership is unchanged: each component manages its own default
executor, while the supplier manages a supplied executor. Clearing a builder's
selection neither shuts down the supplied executor nor changes previously built
instances. See [default executor selection](../../modules/config/advanced-configuration.md#default-executor-selection-for-polling-and-watching).

## Logging

`LogConfig.initClass()` and `LogConfig.configureRuntime()` configure logging once through
class initialization, preserving the existing JVM behavior. Subsequent calls do not reload
the configuration or overwrite application logging changes. Custom providers continue to
implement both `LoggingProvider.initialization()` and `LoggingProvider.runTime()` for
compatibility, but Helidon only invokes `initialization()`.

## Jakarta Libraries

Helidon 28 uses Jakarta EE 11 library versions where available. This dependency
alignment does not establish Jakarta EE 11 platform support or certification.

| Library | Previous version | New version |
| --- | --- | --- |
| Jakarta Annotations | 2.1.1 | 3.0.0 |
| Jakarta CDI API and language model | 4.0.1 | 4.1.0 |
| Jakarta Persistence API | 3.1.0 | 3.2.0 |
| Narayana JTA | 7.1.0.Final | 7.3.4.Final |
| Yasson | 3.0.4 | 3.0.5 |

Jakarta Annotations 3.0 removes `jakarta.annotation.ManagedBean`. Replace any
application references to that annotation. Helidon services use the
[Service Registry annotations](../../modules/injection/injection.md#how-are-services-defined).

Helidon's persistence-unit adapter implements the additional Persistence 3.2
metadata methods. It reports no CDI scope or qualifiers. Applications using
new Persistence API features must choose a provider that implements them.
Custom `PersistenceUnitInfo` implementations must add `getScopeAnnotationName()`
and `getQualifierAnnotationNames()`, returning `null` and an empty list
respectively when no CDI annotations are specified.

The core dependency BOM no longer manages the Hibernate or EclipseLink persistence
providers. They are used only by core tests, which now use Hibernate 7.4.11.Final
and EclipseLink 5.0.2. Applications depending on either provider must supply its
version directly or through a provider-specific BOM.

Narayana now uses CDI 4.1. JBoss Logging is also updated to 3.6.3.Final because
Narayana requires its newer logging API. Applications that enable asynchronous
two-phase transaction processing should review their concurrency and resource
limits: on Java 21 and later, Narayana uses virtual threads for those operations
by default. Asynchronous processing itself remains disabled by default.

Helidon excludes the new transitive `infinispan-core` and `infinispan-commons`
dependencies because their service metadata prevents loading them on the Java
module path. Applications explicitly configuring Narayana's optional Infinispan
transaction store must supply those libraries and use a compatible deployment.
The default transaction store is unaffected.

Yasson's Maven coordinates change from `org.eclipse:yasson` to
`org.eclipse.yasson:yasson`. Update explicit application dependencies;
`helidon-http-media-jsonb` already uses the new coordinates. Java packages and
the JSON-B API remain unchanged. Custom serializers now also apply to values
reached through `Object` properties and annotated interfaces in containers, so
applications using those serializers should verify their JSON output.

See the [Annotations 3.0 release](https://jakarta.ee/specifications/annotations/3.0/),
[Persistence 3.2 SPI](https://jakarta.ee/specifications/persistence/3.2/apidocs/jakarta.persistence/jakarta/persistence/spi/persistenceunitinfo),
[Narayana configuration](https://github.com/jbosstm/narayana/blob/7.3.4.Final/ArjunaCore/arjuna/classes/com/arjuna/ats/arjuna/common/CoordinatorEnvironmentBean.java),
and [Yasson 3.0.5 release](https://github.com/eclipse-ee4j/yasson/releases/tag/3.0.5)
for the upstream changes.
